Every Neovim plugin that talks to an LLM writes its own HTTP client, stream parser, history and credential handling. Its users then set up their API keys again, once per plugin.

Agent SDK does that work once. Your plugin decides what to send and what to show.

<Warning>
Beta, and the API may change. Requires Neovim nightly (0.13-dev).
</Warning>

## What it is

A Lua library that connects your plugin to LLMs over HTTP, and to agents like Claude Code over [ACP](https://agentclientprotocol.com). You start a session with the adapter your user picked, send it prompts, and the replies arrive in your handlers.

## Why use it

- The user sets up adapters and API keys once, and your plugin uses them by name
- One API for HTTP and ACP. Code written against one works on the other
- Replies stream into the same handlers, whether you stream or wait for the whole reply
- The SDK keeps the conversation history
- Tool calls and permission requests arrive as requests for your plugin to answer
- A scripted test adapter, so your tests need no network or API keys

## What you can build

- A chat buffer that talks to Claude Code
- An "explain this selection" command
- A reviewer that comments on your current diff
- A commit message writer

## What it isn't

The SDK is the connection layer only. Your plugin owns everything else:

- **No UI.** Plugins own every buffer and window
- **No agent loop.** Plugins decide what every tool call does and when to stop

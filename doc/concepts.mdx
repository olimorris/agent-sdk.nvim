New to building on LLMs? This page covers every idea the rest of the docs rely on. Each one links to where it's covered in full.

## Adapters

An adapter is how the SDK talks to one provider. There are two kinds:

- **HTTP adapters** send requests to a model's API, like Anthropic's. The model only answers. It can't touch your files
- **ACP adapters** start an agent, like Claude Code, as a separate process and talk to it over the [Agent Client Protocol](https://agentclientprotocol.com). An agent reads files, writes files and runs commands itself

Your plugin uses both the same way. See [Transports](/transports) for why there are two, and the few places they differ.

Your users set up their adapters, and the credentials each one needs, in `agent_sdk.setup()`. Your plugin asks for one by name. See [Configure adapters](/configure/adapters).

## Sessions

A session is one conversation. It holds the adapter, your handlers and the history, so each prompt carries on from the last. A chat window is one session. Closing the window should close the session. See [Sessions](/reference/sessions).

## Prompts and replies

A prompt is what your plugin sends: the user's question, some code, or both. The reply is everything that comes back: the answer, any reasoning, any tool calls, and how many tokens it used.

## Streaming

A model writes its reply a few words at a time. Streaming hands each piece to your plugin as it arrives, so the user watches the answer appear instead of waiting for all of it. Your `text` handler runs once per piece, then `done` runs once with the whole reply.

## Reasoning

Some models think before they answer. That thinking arrives separately from the answer, in your `reasoning` handler, so your plugin can show it, fold it away or ignore it. Not every model or adapter produces it.

## Tool calls

A tool call is the model asking to do something it can't do by itself, like read a file. Who runs the tool depends on the adapter:

- **HTTP:** your plugin runs the tool and sends the result back, and the model carries on with its answer
- **ACP:** the agent runs its own tools, and your plugin follows along

See [Tool calls](/reference/tool-calls).

## Permissions

Before an agent changes anything, like writing a file or running a command, it asks your plugin for permission. Your plugin allows or rejects each request, or asks the user. Without a permission handler, the SDK rejects every request. See [Permissions](/reference/permissions).

## Handlers

Your plugin hears about all of this through handlers, functions you give the session. Each one receives a table, `data`. Most only tell your plugin something: `text`, `reasoning`, `usage`, `tool_update`, `done` and `error`. The two under `request`, `tool_call` and `permission`, ask your plugin for something, and the reply waits until you answer.

Every handler is listed in the [API reference](/reference/api#handlers).

title: "Decide what an agent is allowed to do"

An ACP agent reads files, writes files and runs commands itself. Before it does, it asks your plugin for permission. The user picks the adapter, so any adapter can be an agent, and every session needs a permission policy.

```lua
on = {
  request = {
    permission = function(data)
      local allowed = data.tool_call.kind == "read" or data.tool_call.kind == "search"
      for _, option in ipairs(data.options) do
        if option.kind == (allowed and "allow_once" or "reject_once") then
          return data.respond(option.id)
        end
      end
      data.respond(nil)
    end,
  },
}
```

Work out the policy from the conversation's purpose. A reviewer reads and searches, so this one allows `read` and `search` and rejects everything else.

## The request

| Field | |
| --- | --- |
| `data.tool_call` | The tool call the agent wants to make, with `id`, `title` and `kind` |
| `data.options` | The answers the agent offers, each with `id`, `name` and `kind` |
| `data.respond(option_id)` | Answers with one option's `id`. `data.respond(nil)` cancels |

Tool kinds are ACP's: `read`, `edit`, `delete`, `move`, `search`, `execute`, `think`, `fetch` and `other`.

Option kinds are `allow_once`, `allow_always`, `reject_once` and `reject_always`.

## Rules

- Every path through the handler calls `data.respond()`. The agent waits until it does, so a handler that never responds leaves the reply hanging
- Without a permission handler, the SDK picks the agent's reject option, or cancels the request when the agent offers none

## Asking the user

The handler doesn't have to answer straight away. It can ask the user and respond later:

```lua
permission = function(data)
  vim.ui.select(data.options, {
    prompt = data.tool_call.title,
    format_item = function(option)
      return option.name
    end,
  }, function(option)
    data.respond(option and option.id)
  end)
end
```

Closing the picker without a choice passes `nil`, which cancels.

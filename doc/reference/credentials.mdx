An API key shouldn't sit in your Neovim config, and a plugin shouldn't have to handle one. With Agent SDK, you say where each credential lives, once, in your adapter's `env`. The SDK reads it when it's needed and keeps it out of logs, command lines and plugins.

```lua
require("agent_sdk").setup({
  adapters = {
    anthropic = {
      base = "anthropic",
      env = { api_key = "cmd:op read op://Private/Anthropic_API/credential --no-newline" },
    },
  },
})
```

## Where a credential can live

Each value in `env` is one of:

| Value | Resolves to |
| --- | --- |
| `"ANTHROPIC_API_KEY"` | That environment variable |
| `"cmd:op read op://..."` | The command's output, with trailing whitespace removed |
| `"file:~/.secrets/anthropic"` | The file's contents, with trailing whitespace removed |
| `function(adapter) ... end` | What the function returns |
| `"sk-ant-api03-..."` | The value itself, so a pasted key works |

The SDK tries `cmd:`, `file:` and an environment variable of that name first, and only then uses the value as it is. That fallback also covers values that aren't secrets, like a URL.

A pasted key works, but it lives in your config, which often ends up in a dotfiles repo. Prefer an environment variable or a password manager for anything you'd mind leaking.

`cmd:` works with any password manager that has a command line, such as 1Password's `op`, Bitwarden's `bw`, `pass` or the macOS keychain's `security`. A function runs inside a [`vim.async`](https://neovim.io/doc/user/lua.html#vim.async) task, so it can await slow work of its own.

## How it's used

On an HTTP adapter, `${name}` puts a credential into the adapter's `url`, `headers`, `raw` curl arguments or `parameters`. The built-in adapters already do this, so you only set `env`:

```lua
headers = { ["x-api-key"] = "${api_key}" },
```

On an ACP agent, `env` becomes environment variables for the agent's process, so the names are the ones the agent reads, like `CLAUDE_CODE_OAUTH_TOKEN`. A variable that isn't set isn't passed on. `${name}` also works in the agent's `commands` and `defaults.mcpServers`.

## When it's read

Credentials are read when they're first needed: for an HTTP adapter, at each request, and for an ACP agent, when the agent starts. Neovim starts no faster or slower for having them in your config.

A `cmd:` is the one that can be slow, so it gets more care:

- **It runs in the background.** Neovim keeps working while your password manager waits for Touch ID or a master password
- **It runs once.** Its output is reused for later requests, in the same working directory, so you're asked once
- **Prompts share a run.** Two plugins that prompt at the same moment wait on one run of the command, not two
- **It runs again after a rejected key.** When a provider answers with a 401 or 403, the next request runs the command again, which picks up a rotated key
- **It gives up after 30 seconds.** The prompt then ends in an error that says the command timed out

## Kept out of sight

- **Never logged.** The [log](/reference/logging) never contains `env` or request headers, at any level
- **Never on a command line.** HTTP headers go to curl in a temp file, as `--header @file`, so a key doesn't show in `ps` or your shell's process list. The request body goes the same way, which also keeps a long conversation under the command-line length limits on Linux and Windows
- **Readable only by you.** Those temp files are created with `0600` permissions, and deleted when the request ends or is stopped
- **Never given to a plugin.** A plugin asks for an adapter by name and gets back a session. It never sees `env` or what it resolved to

## When it fails

The prompt ends in an error, and the plugin shows it however it shows errors:

| Error | What to check |
| --- | --- |
| ``the command `op read ...` failed: [ERROR] not signed in`` | The command's own stderr follows. Here, sign in to the password manager |
| ``the command `op read ...` timed out after 30 seconds`` | The command waited for input. Unlock the password manager, or check the command in a terminal |
| `could not read the file ~/.secrets/anthropic` | The file doesn't exist, or you can't read it |
| `401 error: ...` | The provider rejected the key. The next prompt runs a `cmd:` again |

## For plugin authors

Your plugin never handles a credential. Ask for the user's adapter by name with `sdk.adapter()`, start a session, and show the `error` handler's message if a credential can't be read. There's nothing to configure, store or redact on your side.

For tests, the [test adapter](/reference/test-adapter) needs no credentials at all.

Agent SDK ships a test adapter that replays scripted replies. Your tests run with no network access and no API keys set.

Add it through `agent_sdk.setup()`, standing in for the user:

```lua
local scripted = require("agent_sdk.test").adapter({
  replies = {
    {
      { type = "text", text = "Hello" },
      { type = "done" },
    },
  },
})

require("agent_sdk").setup({ adapters = { scripted = scripted } })
require("your_plugin").setup({ adapter = "scripted" })
```

## Scripting replies

Each entry in `replies` is the reply to one request, as a list of events. Each reply ends in a `done` or an `error` event, so a test can script either:

```lua
replies = {
  { { type = "error", message = "overloaded" } },
}
```

A reply with a tool call is followed by a second request once the call is answered, so script both replies.

## Options

| Option | |
| --- | --- |
| `type` | `"http"` or `"acp"`. Defaults to `"http"` |
| `replies` | One list of events per request |
| `model` | The adapter's model |
| `capabilities` | Overrides for `tools`, `vision`, `reasoning` and `models` |

## Testing a permission policy

With `type = "acp"`, a `permission_request` event reaches your plugin's `on.request.permission` handler. It takes `tool_call` and `options` as in [Permissions](/reference/permissions). `scripted.responses` lists the option ids your handlers responded with, in order.

```lua
local scripted = require("agent_sdk.test").adapter({
  type = "acp",
  replies = {
    {
      {
        type = "permission_request",
        tool_call = { kind = "execute" },
        options = {
          { id = "allow", name = "Allow", kind = "allow_once" },
          { id = "reject", name = "Reject", kind = "reject_once" },
        },
      },
      { type = "done" },
    },
  },
})
require("agent_sdk").setup({ adapters = { scripted = scripted } })

-- run your plugin's conversation, then
MiniTest.expect.equality(scripted.responses, { "reject" })
```

An ACP test adapter also behaves like an agent's history: `session:set_messages()` returns `false, err`.

## What to cover

For each conversation in your plugin:

- A reply that streams and ends in `done`
- A reply that ends in `error`
- For each permission policy, one request the policy allows and one it rejects, checked through `scripted.responses`

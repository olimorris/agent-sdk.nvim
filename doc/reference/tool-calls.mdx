A tool call is the model asking your plugin for something, so it arrives in `on.request.tool_call`. A prompt isn't done while a tool call is unanswered. Your plugin answers, and the same prompt carries on.

```lua
on = {
  request = {
    tool_call = function(data)
      if data.name ~= "read_file" then
        return data.fail("Unknown tool: " .. tostring(data.name))
      end
      local text, err = read_file(data.arguments.path)
      if text then
        data.respond(text)
      else
        data.fail(err)
      end
    end,
  },
}
```

`read_file` is your plugin's own function, returning a file's text including unsaved changes.

<Note>
The API for giving an HTTP model your plugin's tool definitions isn't built yet. Until it is, only the [test adapter](/reference/test-adapter) produces tool calls on HTTP.
</Note>

## Answering a call

When `data.needs_result` is `true`, your handler must call `data.respond(content)` or `data.fail(message)`. Once every call in a reply is answered, the SDK sends the results and the prompt carries on. Your plugin sees one `done`, with the whole answer.

A handler that never answers leaves the reply hanging. Without a `tool_call` handler, the SDK fails every call.

## Following a call's progress

`on.tool_update` reports a call's `status`: `pending`, `in_progress`, `completed` or `failed`.

```lua
on = {
  tool_update = function(data)
    set_status(data.id, data.status)
  end,
}
```

On HTTP, the SDK sends `tool_update` once your plugin answers. For a reply that reads one file, the handlers run in this order: `text`, `request.tool_call`, `tool_update`, `text`, `done`.

## On an ACP agent

The same handler runs, but the agent runs its own tools:

- `data.needs_result` is `false`, and `data.respond()` and `data.fail()` do nothing
- `data.name` is `nil`, as ACP has no tool names. Use `data.title` and `data.kind`, and `data.meta` for the agent's own extras
- The agent asks before running a tool. Your plugin answers in a [permission handler](/build/permissions)

## In the reply and history

In `done`, `data.tool_calls` lists every tool call in the prompt, with the latest `status` and `output`. The history pairs every call with its result. See the [walkthrough](/walkthroughs/reply) for the full sequence.

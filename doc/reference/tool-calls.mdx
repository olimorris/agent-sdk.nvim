A tool call is the model asking your plugin for something, so it arrives in `on.request.tool_call`. A prompt isn't done while a tool call is unanswered. Your plugin answers, and the same prompt carries on.

## Giving the model your tools

A model can only call the tools it's told about. List them in the session's `tools`:

```lua
local session = sdk.session({
  adapter = adapter,
  tools = {
    {
      name = "read_file",
      description = "Read a file from the user's project, including unsaved changes",
      parameters = {
        type = "object",
        properties = {
          path = { type = "string", description = "Relative to the project root" },
        },
        required = { "path" },
      },
    },
  },
  on = { ... },
})
```

| Field | |
| --- | --- |
| `name` | Letters, digits, `_` and `-`, starting with a letter or `_`, at most 64 long. Unique in the list |
| `description` | What the tool does and when to use it. The model reads this to decide |
| `parameters` | Optional. A [JSON Schema](https://json-schema.org/understanding-json-schema) with `type = "object"`. Leave it out for a tool that takes no arguments |

The SDK sends the tools with every request in the session, in each provider's own format. `sdk.session()` raises an error when a tool breaks one of the rules above, so a mistake shows up in your plugin and not as a provider's error.

Pass `tools` whatever the adapter. An ACP agent runs its own tools, so it ignores yours. Check `adapter.capabilities.tools` if your plugin needs the model to call them: an adapter without tool support doesn't send them.

### How each API receives them

The format is the one the APIs share: a name, a description and a JSON Schema. Each adapter only moves the fields:

| API | Sent as |
| --- | --- |
| Anthropic | `{ name, description, input_schema = parameters }` |
| OpenAI Chat Completions | `{ type = "function", function = { name, description, parameters } }` |
| OpenAI Responses | `{ type = "function", name, description, parameters }` |
| Gemini | `{ functionDeclarations = { { name, description, parametersJsonSchema = parameters } } }` |

The schema itself is sent unchanged, so use the JSON Schema features every provider you support accepts.

## Answering a call

```lua
on = {
  request = {
    tool_call = function(data)
      if data.name ~= "read_file" then
        return data.fail("Unknown tool: " .. tostring(data.name))
      end
      local text, err = read_file(data.arguments.path)
      if text then
        data.respond(text)
      else
        data.fail(err)
      end
    end,
  },
}
```

`read_file` is your plugin's own function, returning a file's text including unsaved changes. `data.name` is the `name` from your tool's definition.

When `data.needs_result` is `true`, your handler must call `data.respond(content)` or `data.fail(message)`. Once every call in a reply is answered, the SDK sends the results and the prompt carries on. Your plugin sees one `done`, with the whole answer.

A handler that never answers leaves the reply hanging. Without a `tool_call` handler, the SDK fails every call.

## Following a call's progress

`on.tool_update` reports a call's `status`: `pending`, `in_progress`, `completed` or `failed`.

```lua
on = {
  tool_update = function(data)
    set_status(data.id, data.status)
  end,
}
```

On HTTP, the SDK sends `tool_update` once your plugin answers. For a reply that reads one file, the handlers run in this order: `text`, `request.tool_call`, `tool_update`, `text`, `done`.

## On an ACP agent

The same handler runs, but the agent runs its own tools:

- `data.needs_result` is `false`, and `data.respond()` and `data.fail()` do nothing
- `data.name` is `nil`, as ACP has no tool names. Use `data.title` and `data.kind`, and `data.meta` for the agent's own extras
- The agent asks before running a tool. Your plugin answers in a [permission handler](/build/permissions)

## In the reply and history

In `done`, `data.tool_calls` lists every tool call in the prompt, with the latest `status` and `output`. The history pairs every call with its result. See the [walkthrough](/walkthroughs/reply) for the full sequence.
